\FrontSection[notoc]{Project Specification}
\textbf{Problem.} A general language-model agent is not enough for financial analysis: it can invent figures, it calculates poorly in words, and it cannot tell a failed data source from a valid result.

\textbf{Product.} OpenTrading, a harness for financial analysis and market research on Vietnamese equities.
The harness runs the agent loop in a terminal and runs arithmetic as commands.
It instructs the model to take every figure from tool results and checks the figures of its answers against them.
It keeps the investor's constraints in a memory that only the user can change, and asks the user before actions that need approval.
The user connects a model of their choice; the group trains no model.

\textbf{Deliverables.}
\begin{enumerate}
  \item OpenTrading version 0.5.1, released under the Apache 2.0 licence with installable versions for Windows, macOS and Linux.
  \item opentrading-mcp, a market-data server with \num{175} tools whose results state their availability, source and time.
  \item opentrading-benchmark, a comparison of OpenTrading with two general-purpose harnesses on the same model and data.
  \item This report, the time plan and the weekly minutes.
\end{enumerate}

\textbf{Acceptance criteria.} The measures are those of the three objectives in \cref{sec:objective}: automated tests of the rules of the harness and the memory and reliability results of the benchmark; a shared answer contract checked on the tools of the data server; and a paired comparison of the three harnesses, tested with an exact sign test and reported with time and cost.
